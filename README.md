# 申城晨食 · 上海市早餐可达性分析大屏

基于 Vue 3、ECharts 与高德地图 JavaScript API 的 1920×1080 数据可视化大屏。

当前版本使用高德实时查询数据：

- 高德真实底图。
- 高德早餐 POI。
- 高德办公地点 POI。
- 覆盖全部 16 个行政区的早餐 POI 地图点位。
- 配置 Web 服务 Key 后，由服务端按行政区逐页抓取、去重并汇总早餐 POI。
- 未配置 Web 服务 Key 时，自动降级为每区最多 50 个真实 POI 的均衡采样，页面会明确提示。
- 办公地点到最近早餐 POI 的步行距离估算。
- 15 / 20 / 30 分钟可达率。
- 供需缺口代理指数。
- 起点、终点和通勤方式输入。
- 高德公共交通、驾车、步行路线规划。
- 路线附近早餐推荐、绕行时间和含早餐绕行的全程时间。

## 一、最简打开方式

运行环境需要安装 Node.js 20.19 或更高版本。

1. 确认项目根目录存在 `.env.local`。
2. 双击 `启动大屏.cmd`。
3. 浏览器会自动打开大屏。
4. 如果浏览器没有自动打开，查看启动窗口里的 `Local:` 地址，通常为：

```text
http://localhost:5173/
```

如果 5173 端口已被占用，Vite 会自动使用 5174 或下一个可用端口。

## 二、命令行打开方式

在 PowerShell 或终端中进入本项目目录：

```powershell
cd C:\Users\34309\Documents\Codex\2026-10-30\vue-3-echarts-js-api-vue
npm.cmd install --cache .npm-cache
npm.cmd run dev -- --open
```

Windows PowerShell 如果禁止执行 `npm.ps1`，请使用 `npm.cmd`。

## 三、高德 Key 配置

项目根目录的 `.env.local` 用于保存高德配置：

```dotenv
VITE_AMAP_KEY=你的高德 JavaScript API Key
VITE_AMAP_SECURITY_CODE=你的安全密钥
AMAP_WEB_SERVICE_KEY=你的高德 Web 服务 API Key
```

当前工作目录已经配置 JavaScript API Key、JS 安全密钥和 Web 服务 Key。`.env.local` 已加入 `.gitignore`，不会进入 Git 提交和源码包。

高德控制台中建议确认：

1. Key 的服务平台为“Web 端（JS API）”。
2. 另建一个服务平台为“Web 服务”的 Key，填入 `AMAP_WEB_SERVICE_KEY`。
3. 域名白名单包含 `localhost`、`127.0.0.1` 和最终部署域名。
4. POI 搜索、地图 JS API、路径规划的可用额度充足。
5. 更换电脑或部署到新域名时，同步更新域名白名单。

高德 JavaScript API 的 Key 和安全密钥会随网页在浏览器中加载，因此不能只依赖“隐藏源码”。正式部署时务必配置域名白名单，并避免把 `.env.local` 直接发给无关人员。

## 四、地图与数据更新

- 进入页面时优先读取 15 分钟内的真实数据缓存。
- 缓存超过 15 分钟或点击右上角“刷新”，会重新请求高德 POI。
- 服务端将每个行政区切成近邻搜索网格，再对每个网格分页请求。
- 单网格返回满 200 条时，服务端会自动四分该网格继续抓取，直到不再触顶。
- 服务端按 POI ID 去重，并把早餐关键词检索结果按区汇总。
- 前端优先加载服务端全量结果；服务端不可用时才切换为浏览器端区级均衡采样。
- 地图直接显示早餐摊点分布，不再提供“热点 / 可达”切换。
- 左侧改为早餐类型分布，不再展示受 200 条接口上限影响的行政区原始计数。
- 左侧新增供给覆盖质量：行政区覆盖、早餐类型数量、有效坐标率、每区加载点数和数据完整度。
- 全量刷新使用流式进度：显示当前行政区、已完成网格、总网格、已发起请求和已获取 POI 数。
- 地图上的“全市”和“中心城区”按钮用于切换视野。

服务端分页逻辑位于 `server/breakfast-service.mjs`，结果缓存 6 小时。页面存在缓存时会立即打开，不会因全量刷新而阻塞首屏；点击“重试全量”后才启动后台更新。高德 Web 服务有每日调用额度；额度耗尽时会继续使用上次成功的真实数据，并在页面顶部提示，不会伪装成已经完成全量刷新。

## 五、通勤早餐推荐

1. 点击地图右上方的“通勤早餐”。
2. 输入起点和终点。例如输入“华东理工大学”后，系统会列出徐汇校区、奉贤校区、地铁站等多个候选。
3. 必须从候选列表中选择准确地点后才会规划路线，不会自动选择第一个校区。
4. 选择“公共交通”“驾车”或“步行”。
5. 点击“规划路线并推荐早餐”。
6. 页面会绘制高德通勤路线，并按路线距离和 POI 评分推荐最多 6 个早餐点。
7. 点击“清除路线”可删除路线、起终点和推荐点标记。

推荐列表显示：

- 早餐 POI 名称、类别和地址。
- 距通勤路线的距离。
- 从路线往返该 POI 的绕行时间。
- 通勤时间加早餐绕行时间的全程估算。

通勤时间来自高德路径规划。早餐绕行时间按“路径垂直距离往返 ÷ 75 米/分钟”估算，不包含排队、购买和用餐时间。

## 六、指标口径

- 早餐 POI 数量：高德分区检索返回的计数。
- 办公地点样本：高德“写字楼”分区检索返回的计数。
- 步行可达率：办公地点到最近早餐 POI 的距离不超过 `步行时间 × 75 米/分钟` 的比例。
- 平均步行时间：办公地点到最近早餐 POI 的直线距离，按 75 米/分钟换算。
- 供需缺口指数：综合 15 分钟低覆盖程度、办公地点密度和早餐 POI 稀缺度计算出的代理指数。

高德检索计数不等同于政府登记的早餐摊点统计。页面使用“早餐 POI”“检索计数”表述，不做官方口径冒充。

高德不提供官方“上班族早餐需求”统计。当前“可达性”是基于真实办公地点 POI、真实早餐 POI 和距离模型计算的分析结果，不等同于官方人口覆盖率。若接入手机信令、职住人口或真实步行路径服务，可以进一步替换代理模型。

## 七、常见问题

### 页面显示“数据更新失败”

先检查网络，再检查高德 Key 的安全密钥和域名白名单。当前本地开发地址必须允许访问。

### 地图加载但 POI 数量为 0

通常是高德 Key 的服务类型、配额或域名限制问题。可打开浏览器开发者工具的 Network 面板检查高德请求。

### 通勤路线规划失败

确认高德控制台已开通 JS API 路径规划能力，并尝试使用更明确的起终点名称，或直接输入“经度,纬度”。

### 端口被占用

关闭旧终端，或手动指定端口：

```powershell
npm.cmd run dev -- --port 5180 --open
```

### 生产构建

```powershell
npm.cmd run build
npm.cmd run preview
```

构建结果在 `dist/`。部署后仍需在 allowed domain 列表中加入实际域名。

## 八、目录

```text
src/
  assets/shanghai-districts.json  # 上海行政区 GeoJSON
  components/                     # 大屏面板、高德地图与通勤规划器
  data/districts.js               # 行政区元数据与检索配置
  services/amap.js                # 高德加载、POI、路径与指标计算
  lib/echarts.js                  # ECharts 按需引入
  App.vue                         # 页面状态和数据联动
  styles.css                      # 全局视觉系统与响应式布局
server/
  breakfast-service.mjs           # 高德 Web 服务区级分页与去重
  breakfast-api.mjs               # 全量 POI 接口
  index.mjs                       # 生产静态服务与 API 服务
```

行政区边界来源于 DataV.GeoAtlas。地图底图、早餐 POI、办公地点 POI 和通勤路线来源于高德地图。

高德 POI 接口并不能保证覆盖现实中所有未登记的流动早餐摊点。本项目的“全量”指高德 Web 服务在指定关键词、餐饮类型、行政区与分页上限内返回的全部结果。
